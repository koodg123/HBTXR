# Response — Supervision(데이터 증강)의 정당성: Frame/Event Interpolation
*(서술형)*

## 1. 원본 Frame 데이터에서 Saccade가 학습되지 않는 이유

본 데이터셋의 프레임 스트림은 25 Hz, 즉 40 ms 간격으로 취득된다. 우리가 채택한 운동상태 분류는 표준 I-VT(velocity-threshold) 방식으로, 각 프레임에서 추정한 동공 중심의 인접-프레임 속도(px/s)를 판정 물리량으로 삼고, saccade-세션 속도 분포의 90퍼센타일에 해당하는 493 px/s를 임계로 사용한다. 문제는 시간해상도에 있다. 인간의 saccade는 대략 30–80 ms 동안 지속되는 탄도형(ballistic) 운동인데, 40 ms 간격에서는 saccade가 한 프레임과 다음 프레임 *사이*에서 시작되고 종료되어 버린다. 그 결과 두 프레임에 찍힌 동공 중심은 이미 출발 위치와 도착 위치(정착 후)에 가까워, 인접-프레임 변위가 작고 속도가 임계를 거의 넘지 못한다. 즉 saccade라는 사건 자체는 일어났지만 프레임 표현에서는 "거의 정지"로 보이게 된다.

이 한계는 실제 분포에서 그대로 드러난다. EV-Eye 전체(48명, 약 1.49 M 프레임)를 4-state(Fixation/Saccade/Smooth/Blink)로 분류하면, **Saccade 비율이 Train·Val·Test 모든 분할에서 0.00 % 수준**으로 나타난다(아래 Frame Figure). Fixation ≈ 63 %, Smooth ≈ 35 %, Blink ≈ 2 %가 대부분을 차지하고 Saccade는 사실상 비어 있다. 이런 극단적 클래스 부재 상태에서는 어떤 분류기를 학습시켜도 "전부 비-saccade"로 예측하는 것이 손실을 최소화하므로, **Saccade state는 실질적으로 학습이 진행되지 않는다.**

## 2. Event 분포가 알려주는 사실 — Saccade는 "실제로" 풍부하게 존재한다

그렇다면 Frame의 0 %가 곧 "saccade가 드물다"는 뜻일까? 그렇지 않다. 동일한 데이터의 이벤트 스트림을 보면 정반대의 사실이 확인된다. 이벤트 카메라는 동공·홍채 경계가 빠르게 움직일 때 마이크로초 단위로 대량의 이벤트를 발생시키므로, 빠른 운동이 이벤트 밀도의 급증(버스트)으로 직접 기록된다. 우리는 원시 이벤트를 20 ms bin으로 모아 레이트 `rate(ev/s)`를 구하고, 세션 중앙값 `m`을 기준으로 `4·m < rate ≤ 12·m`이면 Saccade, `rate > 12·m`이면 Blink, 그 이하의 비버스트 구간은 세션 성격에 따라 Fixation/Smooth로 분류했다(판정 물리량은 이벤트 레이트, 임계는 세션 중앙의 4배, 시간해상도는 μs~20 ms). 프레임 타임라인과 맞춘 융합 방식에서도 각 프레임의 ±20 ms 창에 포함된 이벤트 수가 세션 중앙의 4배를 넘으면 Saccade로 판정한다.

이 기준으로 산출한 이벤트 분포에서는 **Saccade가 Train 8.4 %, Val 8.7 %, Test 8.6 %로 모든 분할에서 안정적으로 약 8.5 %를 차지한다**(아래 Event Figure). 다시 말해 saccade는 실제로 전체 시간의 약 1/12에 해당할 만큼 빈번하게 일어나고 있으며, **Frame에서 관측된 0 %는 생리학적 사실이 아니라 25 Hz라는 시간해상도가 만든 측정 아티팩트**임을 이벤트 분포가 정량적으로 증명한다.

## 3. 그래서 Frame Interpolation을 적용한다 (자연스러운 귀결)

두 분포의 대비가 곧 증강의 동기이자 설계 지침이 된다. 한편으로 모델의 프레임 경로는 여전히 saccade 상태를 학습해야 하지만 40 ms 프레임으로는 그것을 표현조차 할 수 없고, 다른 한편으로 이벤트는 saccade가 *실제로 얼마나, 그리고 언제* 일어나는지를 정확히 알려준다. 따라서 해결책은 명확하다 — **프레임의 시간해상도를, saccade가 존재한다고 이벤트가 가리키는 바로 그 구간에서 끌어올리는 것**이다.

이를 위해 saccade 구간에 **TimeLens-XL을 적용하여 프레임 스트림을 200 Hz(200 FPS, 5 ms)로 보간**한다. 어떤 구간을 보간할지는 §2의 이벤트 버스트가 자연스럽게 지정해 준다(프레임과 이벤트가 동일한 DAVIS 클럭을 공유함을 확인하였으므로 시점 정합이 가능하다). 간격이 40 ms에서 5 ms로 좁혀지면 하나의 saccade가 6–16개의 (보간된) 프레임에 걸쳐 펼쳐지므로, 인접-프레임 속도가 493 px/s 임계를 넘어 **프레임 표현에서도 saccade가 다시 검출 가능**해진다. 보간 후 분포에서 Saccade는 약 9.3 %(Train 9.33 / Val 9.35 / Test 9.33 %)로 회복되어 이벤트가 가리킨 실제 비율과 일관되며, Fixation·Smooth·Blink는 거의 변하지 않는다. 결과적으로 보간은 없던 사건을 만들어내는 것이 아니라, **이벤트가 증명한 실재하는 saccade를 프레임 표현이 비로소 담을 수 있게 복원**하는 역할을 한다.

## 4. Event Interpolation — 두 스트림의 일관된 조밀화

프레임을 200 Hz로 보간하면 이벤트 쪽도 같은 시간 격자에 맞추어 보강할 필요가 있다. 보간으로 새로 생긴 5 ms 간격의 프레임들을 시간 척도로 삼아, **실제 이벤트가 희소했던 프레임-사이(특히 saccade 전이) 구간**에 대해 인접한 두 보간 프레임의 밝기 변화를 임계화하여(V2E 방식) 합성 이벤트를 생성한다. 프레임과 이벤트가 동일 클럭을 공유하므로 보간 프레임의 타임스탬프를 기준으로 합성 이벤트를 일관되게 정렬할 수 있고, 그 결과 빠른-전이 구간의 이벤트 표현(버스트)이 학습에 충분한 밀도로 제공된다. 요컨대 프레임 보간과 이벤트 보간은 **같은 200 Hz 타임라인 위에서 상호 정합된 한 쌍의 증강**으로 동작한다.

## 5. 검증·무결성·한계

마지막으로, 이 증강이 평가의 공정성을 해치지 않음을 분명히 한다. **보간 데이터는 학습 입력의 증강에만 사용**하며, 검증·시험과 그 정답(GT)은 보간이 아닌 **원본 EV-Eye 실측(실 프레임·실 이벤트·VGG 수동 라벨)** 에 대해서만 산출한다. 보간으로 만든 프레임/이벤트에 대고 정확도를 측정하지 않으므로, 보간기와의 자기일관성을 성능으로 착각하는 순환평가는 발생하지 않는다. 또한 보간 프레임은 추정값이어서 탄도형 saccade가 다소 평활화될 수 있으므로, 보간 결과를 saccade의 *정답*으로 사용하지 않고 입력 표현 보강으로만 활용하며, 학습(실+합성)과 평가(실) 사이의 분포 차이는 sim-to-real gap으로 별도 보고한다. 데이터 분할은 subject-independent(Train 1–36 / Test 37–48, Val = {37,40,45,48})를 따른다.
