## 2. VCK190 Progress

Implemented board-export flow improvements:

- Added board export modes:
  - `reuse-ooc-dcp`: reuse the accelerator OOC `post_route.dcp`.
  - `rebuild-ip`: rebuild through packaged IP.
- Added VCK190 host-only board-export command coverage in the runbooks.
- Added environment sanitization for Vivado batch runs so host HLS/CSIM include
  and library paths do not poison DDRMC / NoC IP generation.
- Added a direct board-export workspace cleanup before rebuilding generated
  Vivado projects.

Latest VCK190 failure analysis:

- Failure log:
  - `workspace/artifacts/build/vck190/vck190_full_deit_tiny_fit/board_export/full_board_export_post_impl.log`
- Symptom:
  - `open_run impl_1` failed with `Run 'impl_1' failed. Unable to open`.
- Root cause from `impl_1/runme.log`:
  - `reuse_ooc_dcp_pre_impl.tcl` could not find the `HGPIPE_VIVADO_0`
    accelerator hierarchy cell before loading the OOC DCP.
- Interpretation:
  - This was not yet a final timing or routing failure.
  - `link_design` completed successfully.
  - The failure happened in the pre-impl hook before `read_checkpoint -cell`
    could load the accelerator checkpoint.

Patch applied:

- `automation/flows/vck190_step5.py` now generates a more robust
  `reuse_ooc_dcp_pre_impl.tcl`.
- The hook now tries exact hierarchy paths and fallback filters based on
  `NAME`, `REF_NAME`, and `ORIG_REF_NAME`.
- The hook prints visible HGPIPE candidate cells if lookup still fails.
- The currently generated board-export hook was patched in-place so the
  existing workspace can be retried without waiting for unrelated source edits.

## 3. ZU15EG Progress

Implemented ZU15EG 3ns resource-fit direction:

- Added a dedicated design config:
  - `configs/designs/zu15eg_full_deit_tiny_fit.json`
- Updated the ZU15EG experiment to use that design config.
- Set both ZU15EG design and target clock periods to `3.0 ns`.
- Kept full model shape rather than switching to a reduced model variant.

Implemented storage-binding support:

- Added common storage-style macros for LUTRAM / BRAM / URAM selection.
- Added `HGPIPE_RESHAPER_BUFFER_STORAGE_STYLE`.
- Added `HGPIPE_ATTN_RESI_FIFO_STORAGE_STYLE`.
- Added `HGPIPE_ATTN_QQ_HEAD_FIFO_STORAGE_STYLE`.
- Kept `HGPIPE_FORCE_RESI_FIFO_URAM` as a compatibility path.
- Applied ZU15EG-specific URAM policy to ATTN reshaper, residual FIFO, and
  QQ-head FIFO buffers.

Implemented ZU15EG case policy:

- `ATTN QKV/R/A` compute parallelism is preserved to avoid recreating the
  previously observed ATTN deadlock.
- `ATTN O-path` remains the safer reduced path.
- `MLP` remains in the ZU15EG fit profile with DSP-enabled multiplication.
- `PATCH_EMBED` keeps the current reduced parallelism and uses target-specific
  URAM weight storage.
- ZynqMP boards other than ZU15EG keep the existing BRAM-forced
  `PATCH_EMBED` weight policy.

## 6. Commit Hygiene

The working tree currently contains generated or runtime artifacts from local
Vivado / HLS / Spinal runs. These should stay out of the progress commit unless
there is a deliberate reason to snapshot generated outputs.

Do not include by default:

- `workspace/artifacts/*`
- `workspace/hardware/SPINAL/latency/*`
- `workspace/hardware/SPINAL/src/main/verilog/*`

Do include:

- Source changes under `automation/`.
- Config changes under `configs/`.
- ZU15EG case/source changes under `workspace/hardware/case_zu15eg/` and
  `workspace/hardware/src/`.
- Documentation changes under `docs/`.
