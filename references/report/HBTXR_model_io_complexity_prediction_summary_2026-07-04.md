## Ground Rules

- Measured MACs are `thop.profile` CPU dummy-input MACs from the local HBTXR comparison setting.
- FLOPs are reported as `2 * MACs`.
- `B` is batch size and `T` is sequence length.
- `Not measured` means no HBTXR 64x64 dummy-input profile exists in the local comparison CSV. It is not a zero value.
- `Blocked` means the original codebase cannot be imported in the current `.venv` because required runtime packages or ABI-compatible Python/CUDA packages are missing.
- For center-only models, final prediction means the center point used for pixel-error distance. Those models do not directly predict ellipse axes/angle/mask unless an extra reconstruction heuristic is added.
- For heatmap/ellipse models, the raw head output is separated from the decoded final prediction.

## Fair-Comparison Notes

- HBTXR and EPNet/FECET are the measured targets here with native ellipse heads (`hm`, `ab`, `trig`, `reg`, `mask`). EIDet/ElNet is listed in the same target-column format and also has native ellipse-style heads (`hm`, `ab`, `ang`, `reg`, `mask`), but its Params/MACs/FLOPs are not profiled in the HBTXR 64x64 table and its input contract needs adaptation.
- Retina, TDTracker, ERVT, TENNs-Eye, FACET TennSt, and BRAT are center or box/center predictors in this HBTXR port. Pixel-error distance is fair if all predictions and labels are scaled to the same 64x64 coordinate frame, but ellipse IoU is not fair without a fixed, model-independent reconstruction rule.
- EV-Eye, E-Track, EX-Gaze, and Swift-Eye were profiled with their original codebase input sizes. E-Track, EX-Gaze, and Swift-Eye required additional isolated venvs because their framework stacks conflict with the main `.venv`.
- TDTracker has the largest measured MACs because it processes a 100-frame sequence with 3D convolution, GRU, and Mamba-style temporal layers, then predicts x/y distributions over the output grid.
- Retina has the fewest parameters and MACs among the measured targets, but its output is a box head, not a native pupil ellipse head.
- `FACET_TennSt` and `TENNs_Eye` share the same measured complexity in this table because the local measured configuration uses the same TennSt architecture/input contract.

## Profiling Notes

- EIDet/ElNet measurement command used `.venv`, `thop`, input `1x3x256x256`, FACET model-factory heads, and a local DCNv2 shim because `DCNv2` is not present in the repository. Treat this as a reproducible proxy for the FACET ElNet configuration, not as a compiled-DCNv2 runtime profile.
- EV-Eye measurement used `.venv`, `thop`, and input `1x1x260x346`.
- E-Track measurement used `tmp/venvs/etrack_py38`, TensorFlow 2.6.0, and external `jakeret/unet` commit `f557a51`. Keras custom block internals are not exposed as top-level layers, so MACs were computed from the installed source using Conv2D/Conv2DTranspose dimensions; Conv2DTranspose uses the same output-spatial convention as common FLOPs counters. Params matched `model.count_params()`.
- EX-Gaze measurement used `tmp/venvs/exgaze_py310`, `thop`, input `1x1x160x256`, and the full-eye-pupil RetinaHead config. PyPI `mmrotate==1.0.0rc1` was used because the README references a separate develop checkout that is not present in this repo; a local `collections.Sequence` compatibility alias was needed for Python 3.10 import.
- Swift-Eye measurement used `tmp/venvs/mmrotate_py38`, local Swift-Eye MMRotate code, MMCV `get_model_complexity_info`, input `1x3x352x352`, and a valid-proposal monkey patch for the official `forward_dummy` path because the upstream dummy proposals are random and can violate ROIAlign width/height assertions. The reported FLOPs include the RoITransformer dummy path with 1000 ROI proposals.
