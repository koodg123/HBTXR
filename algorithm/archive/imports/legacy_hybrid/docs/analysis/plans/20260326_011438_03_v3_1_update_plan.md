## 요약

- 이 문서는 `HBTXR_v3_0`를 `mode-aware` 구조로 확장하던 `v3.1` 전환 계획을 정리한다.
- 핵심 변화는 아래와 같다.
  - `mode0 = Raw CSV Supervision`
  - `mode1 = Event Voxel`
  - `mode2 = Frame Interpolation`
- `mode1`은 계속 baseline으로 유지한다.
- `canonical1/2`, `manifest1/2`, mode-aware loader routing, 공통 run contract를 도입한다.
- Stage1 DeiT-Tiny selective preload, loss catalog 확장, optional `SSL / pruning` wiring을 포함한다.
- active YAML preset은 inline comment로 self-describing하게 유지한다.

## 계획된 구현 영역

### 1. Preprocess / Canonical / Manifest

- `mode1`
  - raw frame + raw event + Grounded-SAM
  - manifest에 event voxel provenance 저장
- `mode2`
  - raw frame + raw event
  - interpolation cache
  - synthetic-frame annotation path
  - synthetic provenance를 canonical / manifest에 저장

### 2. Dataloader 분리

- `loader_mode1`
  - event binning + accumulation + voxel building
- `loader_mode2`
  - synthetic timestamp alignment 및 interpolation metadata를 `meta`에 제공
- shared factory
  - `make_loader_by_mode(cfg, manifest_path, shuffle)`

### 3. Stage1 / Stage2

- `stage1`
  - frame-centric eye region, pupil state, mask supervision
- `stage2`
  - frame-event hybrid offset tracking
- 두 stage 모두 mode-aware하게 동작

### 4. Pretrained loading

- Stage1-selective DeiT-Tiny preload
- shape-safe selective loading
- report를 `hypers/`에 저장

### 5. Loss library

- loss catalog 전부 구현
- active stage wiring은 안정적으로 유지
- `compute_stage1_losses`, `compute_stage2_losses`, `compute_metrics` 유지

### 6. SSL / Pruning

- `SSL`
  - EMA teacher-student
  - feature / state / prediction similarity
  - optional KD / RKD
- `pruning`
  - implicit width slicing
  - width candidate sampling
  - student-width inference path
- 두 기능 모두 config 기본값은 `disabled`
