알고리즘 수준 차이 있음.

- 상류 소스 경로/URL:
  - `https://raw.githubusercontent.com/AGI-Arena/MARS/main/MARS/optimizers/mars.py`
- HBTXR 반영 경로:
  - `src/hbtxr/optim/mars.py`
- 동일하게 유지된 부분:
  - `MARS` optimizer core
  - `update_fn(...)`
  - approximate MARS step path
  - exact MARS update ordering
    - future-group gradient pass
    - `update_previous_grad()`
    - current-group gradient pass
    - optimizer step
    - `update_last_grad()`
- 변경한 부분:
  - `build_mars_optimizer(...)` builder를 추가했습니다.
  - upstream의 `@torch.compile`이 붙은 `NewtonSchulz`는 제거하고 eager 함수 본문만 유지했습니다.
  - `is_approx=false`일 때 upstream의 무한 `get_batch(...)` 루프 대신 finite-loader 기반 exact multi-pass trainer path로 연결했습니다.
  - future pass에서 gradient가 없는 파라미터는 `update_previous_grad()`가 `previous_grad`를 zero-fill 하도록 바꿨습니다.
  - `update_last_grad()`는 `previous_grad` state가 없어도 실패하지 않고 `last_grad`를 0으로 유지하도록 완화했습니다.
- benchmark 해석 메모:
  - HBTXR에서는 approximate와 exact MARS를 모두 쓸 수 있습니다.
  - exact 경로의 순서는 공식 계약을 따르지만, finite dataset 처리와 missing-gradient zero-fill은 HBTXR 통합용 변경입니다.
  - 현재 회귀는 CPU 경로만 검증됐고, exact MARS 전용 CUDA benchmark는 별도로 수행하지 않았습니다.
