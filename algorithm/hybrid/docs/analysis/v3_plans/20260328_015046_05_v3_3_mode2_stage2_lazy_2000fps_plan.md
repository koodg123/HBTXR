# HBTXR v3.3 Mode2-Stage2 Lazy 2000FPS 계획

Last updated: 2026-03-28 KST

## 요약

- `2000 FPS` full materialization은 `mode2`의 기본 경로로 현실적이지 않다.
- 실질적인 목표는 아래를 유지하는 새로운 `mode2-stage2` 전용 lazy 경로를 만드는 것이다.
  - target timestamp scheduling
  - pair-local event indexing
  - on-the-fly synthetic frame generation
  - on-the-fly 또는 cached synthetic event generation
- `Stage1`은 이번 변경의 핵심 경로가 아니다.
- 이 계획의 주 목적은 모든 synthetic frame을 persistent file artifact로 저장하거나 색인하지 않고도 `2000 FPS` 학습을 가능하게 하는 것이다.

## 목표

- `target_fps=2000`에서 `mode2-stage2` 학습이 가능하도록 만든다.
- full synthetic PNG 또는 per-sample materialization을 피한다.
- 현재 `Stage1 / Stage2`, `mode1 / mode2`, `canonical / manifest` 계약을 최대한 유지한다.
- 별도의 비호환 경로를 새로 만들지 않고, 현재 `target-FPS session-store` 방향을 재사용한다.

## 문제 정의

현재 관측된 scaling은 다음과 같다.

- `500 FPS`: `46,367,140` frames
- `1000 FPS`: `92,733,912` frames

따라서 `2000 FPS`는 대략 아래 수준으로 예상된다.

- approximately `185,467,456` frames

이 규모는 현재 fully materialized `mode2` 경로를 아래 측면에서 비현실적으로 만든다.

- storage
- preprocessing time
- manifest size
- training sample enumeration
- 반복 실험 비용

## 잠금 결정

- `2000 FPS` 지원은 `mode2-stage2` 우선 과제이지 `mode2-stage1` 우선 과제가 아니다.
- `Stage1`은 high-rate synthetic event generation의 설계 중심이 아니다.
- `mode2-stage2`는 lazy schedule-driven 경로로 이동한다.
- lazy 경로에서 synthetic frame은 기본적으로 전체 PNG corpus로 저장하지 않는다.
- authoritative dense source는 계속 session store로 유지한다.
  - raw frames
  - raw event stream
  - target timestamp schedule
- `pair-local + source_pair_average + alpha`는 계속 유효한 Stage2 event-generation 전략으로 유지한다.
- exact interval index가 가능한 경우 `target_fps_session_store`가 가장 faithful한 event contract다.

## 범위

이 계획은 아래를 다룬다.

- `mode2-stage2`
- `target_fps >= 2000`
- lazy schedule-based training
- dataset / loader / manifest / schedule 변경

이 계획은 아래를 요구하지 않는다.

- `mode1` 교체
- 기존 materialized `mode2` 삭제
- Stage1 objective 재설계
- Stage2 model head 또는 loss 정의 변경

## 비목표

- full-dataset `2000 FPS` PNG export를 기본 workflow로 만들지 않는다.
- 이 단계에서 모델 아키텍처를 재설계하지 않는다.
- Stage1과 Stage2 data semantics를 합치지 않는다.
- 첫 lazy 구현에서 TimeLens를 필수 의존성으로 두지 않는다.
- 첫 단계에서 legacy materialized `mode2` 지원을 제거하지 않는다.

## 목표 아키텍처

목표 경로는 아래와 같다.

1. target timestamp schedule 생성
2. source frame과 raw event를 session storage에 유지
3. schedule metadata를 포함한 compact canonical / manifest row 작성
4. `__getitem__` 내부에서 frame / event input 합성
5. 필요 시 첫 접근 이후 synthesized tensor를 cache

즉 authoritative object는 아래가 된다.

- session store
- target-FPS schedule
- compact canonical row
- compact manifest row

그리고 더 이상 아래가 중심이 아니다.

- target timestamp마다 materialized synthetic frame file

## 왜 현재 경로만으로는 부족한가

현재 경로는 여전히 materialized synthetic row와 optional synthetic frame artifact 비중이 높다.

이 구조는 아래 상황에서는 괜찮다.

- interpolation rate가 낮을 때
- debugging
- Stage1 exploration

하지만 아래에는 맞지 않는다.

- `2000 FPS`
- 장시간 session
- 반복적인 Stage2 실험

현재 병목:

- physical frame artifact가 너무 많다.
- duplicated payload를 담은 manifest row가 너무 많다.
- preprocessing work가 반복된다.

## 권장 데이터 계약

### 1. Session Store

하나의 session store를 dense source of truth로 유지한다.

최소 포함 요소:

- raw frame tensor 또는 reopen 가능한 raw frame reference
- raw frame timestamps
- raw event stream
- target timestamp schedule
- target event index ranges

### 2. Target-FPS Schedule

각 target timestamp row는 아래를 포함해야 한다.

- `sample_timestamp_us`
- `frame_pair_index`
- `source_timestamp_pair_us`
- `interp_alpha`
- `synthetic_frame_flag`
- `event_index_range`
- optional `prev_event_index_range`

이 객체가 lazy 경로의 핵심 표현이 된다.

### 3. Canonical Row

canonical row는 supervision-first 원칙을 유지한다.

유지할 것:

- pupil state
- ROI supervision
- annotation quality / status
- interpolation provenance

하드 요구사항에서 빼야 할 것:

- full synthetic frame file path

### 4. Manifest Row

manifest row는 compact schedule reference가 되어야 한다.

권장 필드:

- `sample_id`
- `annotation_ref`
- `prev_annotation_ref`
- `session_store_path`
- `session_store_format`
- `frame_pair_index`
- `sample_timestamp_us`
- `source_timestamp_pair_us`
- `interp_alpha`
- `event_index_range`
- `synthetic_frame_flag`
- `data_mode`
- `frame_source`

## Lazy Frame Generation 계약

`mode2-stage2` lazy row에서:

- session store에서 source frame pair `(f0, f1)`를 다시 연다.
- `interp_alpha`를 계산한다.
- `dataset.__getitem__` 안에서 현재 sample frame을 생성한다.

후보 backend:

- `linear_blend`
- optional `timelens`

첫 단계 우선순위:

- `linear_blend`

이유:

- deterministic
- 빠름
- 이미 통합되어 있음

## Lazy Event Generation 계약

현재 Stage2 oriented synthetic event 전략은 유지한다.

- `generation_strategy: source_pair_average`
- `source_pair_scope: pair_local`
- `average_weighting: alpha`

운영 의미:

- left interval: `[t0, t_syn]`
- right interval: `(t_syn, t1]`
- 최종 event tensor:
  - `(1 - alpha) * left + alpha * right`

더 높은 fidelity를 위한 권장 경로:

- schedule 안에 `event_index_range`가 있으면 exact interval-backed event selection을 우선 사용
- pair-local mixing은 선택된 experiment contract일 때만 사용

## 실행 모드

### A. 기존 Mode2 Materialized

유지 용도:

- debugging
- visual inspection
- 낮은 interpolation rate
- backward compatibility

### B. 신규 Mode2 Lazy Target-FPS

추가 용도:

- `2000 FPS` Stage2
- large-scale experiments
- reduced storage workflow

권장 config 예시:

```yaml
data:
  mode: mode2
  mode2:
    execution: lazy_target_fps
    interpolation:
      backend: linear_blend
      target_fps: 2000
    synthetic_event_builder:
      generation_strategy: source_pair_average
      source_pair_scope: pair_local
      average_weighting: alpha
```

## 파일별 계획

### 1. `src/hbtxr/preprocess/target_fps_build.py`

추가 또는 확장:

- target timestamp schedule export
- compact schedule metadata
- frame-pair index mapping
- target timestamp용 event interval indexing

### 2. `src/hbtxr/preprocess/target_fps_canonical.py`

lazy row가 아래를 참조할 수 있도록 canonical writing 확장:

- source frame pair
- `interp_alpha`
- target timestamp
- schedule-backed event interval metadata

### 3. `src/hbtxr/preprocess/build_manifests.py`

`mode2-stage2`용 compact lazy manifest path 추가

요구사항:

- row는 train / eval / infer 호환성을 유지해야 한다.
- large duplicated payload는 피해야 한다.
- source-pair provenance는 유지해야 한다.

### 4. `src/hbtxr/data/dataset.py`

lazy frame 경로 추가:

- synthetic frame file이 없더라도
- source frame pair metadata가 있으면
- on the fly로 frame 생성

event generation 확장:

- exact schedule event interval 우선
- 설정되어 있으면 pair-local mixing 차순위

### 5. `src/hbtxr/data/loader.py`

추가:

- `mode2.execution: materialized | lazy_target_fps`

그리고 그에 맞춰 dataset kwargs routing

### 6. `configs/base.yaml`

추가:

- `data.mode2.execution`
- `data.mode2.lazy_cache.*`
- optional `data.mode2.schedule.*`

### 7. `configs/mode2_stage2.yaml`

향후 권장 기본값:

- `execution: lazy_target_fps`

단, 임시 escape hatch로 materialized mode 복귀 옵션은 남긴다.

## Optional Lazy Cache

같은 synthetic tensor를 epoch마다 다시 만들지 않도록:

- first read 시 sample-level cache 허용
- cache key는 아래를 포함
  - source frame pair
  - `interp_alpha`
  - resize policy
  - event generation strategy
  - event generation scope
  - event builder params

가능한 출력:

- `cache/mode2_lazy/<sample_hash>.npz`

저장 항목:

- interpolated frame tensor
- event tensor
- minimal metadata

## 전환 전략

### Phase 1

- current materialized `mode2` 유지
- lazy schedule metadata와 dataset support 추가

### Phase 2

- preset 기준 `mode2-stage2`가 lazy mode를 우선 사용
- materialized mode는 fallback으로 유지

### Phase 3

- 실데이터 기준 storage / speed 비교 수행
- high-rate materialized mode를 deprecated 할지 결정

## 리스크

- 너무 이른 시점에 manifest field를 줄이면 compatibility가 흔들릴 수 있다.
- on-the-fly frame synthesis는 cache가 없으면 CPU 병목이 될 수 있다.
- TimeLens-backed lazy synthesis는 기본 경로로 쓰기엔 너무 느릴 수 있다.
- pair-local mixing은 synthetic contract이며 exact runtime event causality와 동일하지 않다.
- cache policy가 좋지 않으면 data-loader worker memory pressure가 증가할 수 있다.

## 완료 기준

- `target_fps=2000`에서 full synthetic frame export 없이 `mode2-stage2`가 실행 가능
- manifest row가 active training pipeline에서 계속 load 가능
- dataset이 source-pair metadata만으로 synthetic frame tensor를 재구성 가능
- dataset이 schedule / pair-local metadata만으로 synthetic event tensor를 재구성 가능
- Stage2 train smoke가 lazy path에서 통과
- lazy-built Stage2 checkpoint에서 inference와 export가 계속 동작
- storage footprint가 full materialized path보다 의미 있게 작음

## 우선순위

1. target-FPS schedule representation
2. compact manifest contract
3. dataset lazy frame generation
4. dataset interval-backed event generation
5. Stage2 smoke validation
6. lazy cache
7. optional TimeLens lazy backend
