# HBTXR_v3_0 Initial Plan

이 문서는 `HBTXR_v3_0` 작업 초기에 합의했던 첫 번째 계획 문서를 보존용으로 정리한 것입니다.
이후 ABI, 데이터 계약, 실험 워크플로, legacy 정리 내용은 별도 문서에서 계속 확장되었습니다.

관련 문서:
- `docs/chat/20260326_011438_01_v3_update_history.md`
- `docs/chat/20260326_011438_02_v3_progress_checklist.md`
- `docs/chat/20260326_011438_03_v3_conversation_and_decision_log.md`

## Initial Goal

- `baseline/HBTXR-v2_1-main`를 기반으로 `HBTXR_v3_0`을 독립 버전으로 구현한다.
- `25-28`개의 Markdown 문서를 기준으로 설계를 구체화한다.
- `references_repo/FACET`를 참고해 annotation 방식, dataset 구성 방식, loss prior를 흡수한다.
- `baseline/grounded-segment-anything`을 이용해 dense annotation 작업을 수행한다.
- 모델 backbone과 기본 hybrid tracking 구조는 `baseline/HBTXR-v2_1-main`을 유지한다.

## Summary

- `HBTXR_v3_0`는 기존 baseline을 직접 덮어쓰지 않고 별도 버전으로 관리한다.
- 1차 구현 순서는 `Annotation -> Dataset/Training -> Runtime`으로 고정한다.
- 핵심 목표는 새 모델을 처음부터 다시 만드는 것이 아니라, 더 나은 annotation truth와 dataset contract를 통해 `HBTXR-v2_1-main`을 `v3.0`으로 고도화하는 것이다.
- `FACET`은 주 모델로 그대로 이식하지 않고, annotation 포맷, ellipse supervision, loss 설계, 데이터 export 기준의 참고 모델로 사용한다.

## Analysis

- `HBTXR-v2_1-main`은 이미 hybrid tracking, geometry-aware regression, search/track 흐름을 갖고 있으므로 `v3.0`의 핵심 변화는 데이터와 supervision 품질 향상에 있다.
- `FACET`은 dense annotation 기반 데이터셋과 ellipse 중심 supervision 구조를 갖고 있어, `HBTXR_v3_0`의 annotation/canonical/dataloader 설계에 직접적인 기준점이 된다.
- 따라서 `v3.0`의 본질은 `HBTXR backbone 유지 + FACET식 데이터/annotation/loss prior 도입`으로 정리할 수 있다.

## Strategy

### 1. Repository Strategy

- `HBTXR_v3_0`을 별도 루트로 생성한다.
- 기존 `baseline/HBTXR-v2_1-main`은 참조용 baseline으로 유지한다.
- 패키지 구조와 기본 학습 파이프라인은 최대한 유지하되, 데이터 계약과 실험 디렉토리 체계를 `v3.0` 기준으로 재정의한다.

### 2. Annotation Strategy

- `baseline/grounded-segment-anything`을 dense annotation assistant로 사용한다.
- 입력 단위는 frame ROI, eye ROI, 이전 ellipse 또는 초기 box prompt로 둔다.
- 출력 truth는 다음 항목을 canonical source로 저장한다.
  - eye region bounding box
  - pupil mask
  - pupil region
  - ellipse `(x, y, a, b, theta)`
  - state `(x, y, a, b, u, v)`
  - annotation quality
  - annotation source
  - closed-eye / validity flags
- 검수 기준은 `val/test`는 전수 검수, `train`은 seed 수동 검수 + low-quality 샘플 추가 검수로 시작한다.

### 3. Canonical and Dataset Strategy

- 단일 canonical truth source를 중심으로 모든 export를 생성한다.
- session 단위 저장 구조 안에 `masks`, `ellipse store`, `annotation qc`, `events`를 함께 관리한다.
- 하나의 canonical truth에서 두 방향의 활용이 가능하도록 한다.
  - `HBTXR` 학습용 manifest-first 포맷
  - `FACET` 스타일 분석/비교/export 포맷
- split 기본값은 subject-independent 전략을 사용한다.

### 4. Training Strategy

- 모델은 우선 `baseline/HBTXR-v2_1-main`의 hybrid tracker 구조를 유지한다.
- loss는 `HBTXR-v2_1-main`의 안정적인 search/track loss를 기반으로 두고, `FACET`의 geometry prior와 ellipse supervision 비율을 반영한다.
- annotation quality와 closed-eye 정보를 loss gating에 포함한다.
- 초기 단계는 아래 3종 config를 기준으로 시작한다.
  - `stage1_frame_v3`
  - `stage2_hybrid_v3_mode1`
  - `stage2_hybrid_v3_mode2`

### 5. Runtime Strategy

- runtime은 1차 우선순위가 아니라 annotation/data/training 이후 단계로 둔다.
- 이후 단계에서 similarity 계산과 FSM 기반 search/track 전환을 host side에서 정리한다.
- accelerator 대상은 dense inference 중심으로 두고, annotation/event build/FSM은 host side에서 처리한다.

## Execution Readiness

### Phase A. Annotation and Canonical

완료 기준:
- 하나의 session에서 `mask -> ellipse -> canonical store -> training manifest`가 모두 생성된다.

확인 항목:
- empty mask 처리
- multi-blob mask 처리
- ellipse fitting 실패 처리
- timestamp mismatch 처리

### Phase B. Dataset and Training

완료 기준:
- `stage1/stage2` smoke training이 작은 subset에서 `NaN` 없이 완료된다.

확인 항목:
- dataloader batch shape
- loss smoke test
- baseline ABI 회귀 여부
- annotation quality / closed-eye gating 동작 여부

### Phase C. Runtime Upgrade

완료 기준:
- offline replay에서 search/track 전환 이유가 로그로 남고, similarity 저하 시 relocalization이 발생한다.

확인 항목:
- similarity sanity test
- controller transition test
- subject-independent evaluation result table 생성

## Advantages

- `HBTXR-v2_1-main`의 안정된 baseline을 재사용하므로 연구 리스크를 줄일 수 있다.
- `FACET`의 강점을 dataset/annotation/loss 설계에 흡수하면서도 전체 모델을 새로 재구현하는 비용을 피할 수 있다.
- `Annotation -> Dataset/Training -> Runtime` 순서를 통해 실패 지점을 단계별로 격리할 수 있다.

## Risks

- Grounded-SAM 기반 mask drift가 ellipse supervision을 오염시킬 수 있다.
- pseudo label 품질이 낮으면 consistency 또는 geometry loss가 오히려 성능을 떨어뜨릴 수 있다.
- canonical truth와 export 결과가 분리되면 디버깅 비용이 급격히 커질 수 있다.

## Mitigation

- canonical mask/ellipse store를 단일 source of truth로 유지한다.
- `annotation_quality`, `mask_valid`, `closed_eye_flag`를 loss gating의 필수 입력으로 둔다.
- val/test는 반드시 수동 검수 비중을 높여 benchmark 신뢰도를 확보한다.

## Initial Assumptions

- 원천 데이터는 기존 HBTXR가 다루던 eye-tracking session 구조를 계속 사용한다.
- `grounded-segment-anything`은 offline annotation assistant이며 runtime 모델에는 직접 포함하지 않는다.
- `FACET`은 benchmark/export/loss reference 용도이고, `v3.0`의 주 모델은 `HBTXR` 계열 backbone을 유지한다.
- 첫 번째 완료선은 `annotation + canonical + dataset + v3 training config + smoke training`이다.
