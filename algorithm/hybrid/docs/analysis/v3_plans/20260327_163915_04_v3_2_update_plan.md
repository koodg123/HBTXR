# HBTXR v3.2 전환 계획

Last updated: 2026-03-27 KST

## 요약

- 이 문서는 `raw -> canonical -> manifest` 경로를 단일 `target_fps` 기반 dataset build 계약으로 재구성하던 `v3.2` 전환 계획을 정리한다.
- 핵심 방향은 다음과 같다.
  - `mode1`과 `mode2`를 서로 다른 데이터셋 체계로 보지 않고, 같은 target-timestamp grid 위에서 생성한다.
  - dataset build, annotation fusion, storage rule을 현재 저장소와 호환되게 유지하되 직접 구현 가능한 수준으로 명시한다.
  - session store를 authoritative source로 두고 canonical / manifest는 bridge layer로 사용한다.
- 이 문서는 이후 `05_v3_3...`, `09_v3_7...` 문서에서 lazy mode2와 Grounded-SAM closure를 분리하기 전의 통합 설계 기준이다.

## 목표

- `target_fps` 중심의 dataset build 계약을 명시한다.
- `mode1`, `mode2` 모두를 같은 target timestamp grid에서 생성한다.
- canonical / manifest workflow는 현재 저장소와 호환되게 유지한다.
- dataset build, annotation fusion, storage 규칙을 구현 가능한 수준으로 잠근다.

## 잠금 결정

- `target_fps`는 새로운 dataset build 경로의 명시적 입력이자 필수 설계 파라미터다.
- frame interpolation은 기존 `src/hbtxr/preprocess/interpolation.py` 계약을 사용한다.
  - `linear_blend`
  - `timelens`
- interpolation은 sensor size에서 수행한다.
- dataset build 단계에서 pre-canonical resize는 도입하지 않는다.
- event generation은 synthetic DVS stream 생성이 아니라 **rebinned existing events**를 의미한다.
- session storage는 `H5 + JSONL` 조합을 사용한다.
  - dense session array는 per-session `H5`
  - canonical index와 manifest는 `JSONL`
- eye ROI supervision은 항상 `Grounded-SAM`을 사용한다.
- `Raw-CSV`는 pupil-state supervision only로 간주한다.
  - CSV가 있으면 `pupil_bbox`, `pupil_mask`, `pupil_state`를 파생
  - `eye_region_mask`, `eye_region_bbox`는 CSV로 backfill하지 않음
- pupil supervision precedence
  - `Raw-CSV` pupil state
  - `Grounded-SAM-in-ROI`
- `Raw-CSV`가 없는 경우 Grounded-SAM 순서는 고정
  1. `eye_region_mask`
  2. `eye_region_bbox`
  3. `eye_region_bbox`로 ROI crop
  4. ROI 내부 `pupil_mask`
  5. `pupil_bbox`, `pupil_state (x, y, w, h, theta)`
- frame row는 annotation partial failure 때문에 drop하지 않는다.
  - failure / fallback은 status / reason field로 기록
  - session-level fatal failure만 skip

## 명확해진 계약

### 1. Target Timestamp Grid 계약

- `target_fps`는 fixed target step을 정의한다.
  - `target_step_us = round(1_000_000 / target_fps)`
- grid는 session의 첫 raw-frame timestamp에 anchor된다.
  - `t0 = first_raw_frame_timestamp_us`
- target timestamp 생성식
  - `t_i = t0 + i * target_step_us`
  - `t_i <= last_raw_frame_timestamp_us`일 때만 유지
- 마지막 raw frame을 억지로 포함시키기 위한 extra off-grid timestamp는 추가하지 않는다.
- raw-frame reuse rule
  - raw frame timestamp가 정확히 `t_i`와 같으면 그 frame을 재사용
  - 아니면 enclosing raw-frame pair에서 interpolation

이 규칙으로 target grid는 다음 성질을 가진다.

- deterministic
- monotonic
- raw-frame time range 안에 bounded

### 2. Event Packet Boundary 계약

- target event packet은 causal하고 non-overlapping이다.
- target timestamp `t_i`의 canonical time window:
  - 첫 target frame
    - `(session_event_start_timestamp_us, t_i]`
  - 이후 target frame
    - `(t_{i-1}, t_i]`
- event index range는 half-open indexing
  - `event_index_range = [start_idx, end_idx)`
  - `event_count = end_idx - start_idx`
- `end_idx`는 timestamp가 `t_i`보다 엄격하게 큰 첫 event index
- empty packet 허용
  - `start_idx == end_idx`
  - row는 유지
  - explicit packet/status metadata 기록
- `event_end_timestamp_us`는 실제 마지막 event timestamp가 아니라 target frame timestamp로 정의
  - sparse / empty packet이어도 target grid와 정렬된 계약 유지

### 3. Eye-State 계약

- `eye_state_flag`는 필수 필드다.
- 허용값
  - `open`
  - `closed`
- `closed`는 아래를 모두 포함
  - blink frame
  - fully closed-eye frame
  - 기타 eyelid-closed state
- ROI / pupil annotation이 불안정하더라도 `eye_state_flag`는 항상 존재해야 한다.
- mismatch / uncertainty는 아래로 표현한다.
  - `annotation_status`
  - `annotation_reason`
  - `roi_status`
  - `pupil_status`
- 즉 `eye_state_flag`는 binary state field이고, 오류나 모호성은 status/reason으로 분리 추적한다.

### 4. H5 Physical Schema 기준

- logical schema는 고정
- 초기 physical encoding baseline은 아래와 같다.
  - `/frames/image_u8`
    - shape: `[N, H, W]`
    - dtype: `uint8`
  - `/frames/timestamp_us`
    - shape: `[N]`
    - dtype: `int64`
  - `/frames/source_pair_index`
    - shape: `[N, 2]`
    - dtype: `int32`
    - raw-reused frame은 `[-1, -1]`
  - `/frames/interp_alpha`
    - shape: `[N]`
    - dtype: `float32`
    - raw-reused frame은 `0.0`
  - `/events/raw/x`, `/events/raw/y`
    - dtype: `uint16`
  - `/events/raw/timestamp_us`
    - dtype: `int64`
  - `/events/raw/polarity`
    - dtype: `int8`
  - `/events/target/start_idx`, `/events/target/end_idx`
    - dtype: `int64`
  - `/events/target/event_count`
    - dtype: `int32`
  - `/labels/*state*`, `/labels/*bbox*`, `/labels/*quality*`
    - categorical을 제외하면 기본 `float32`
  - categorical status/source field
    - H5 내부 integer-coded array
    - `/meta` JSON enum으로 decode

writer 기본값:

- dense array는 gzip compression 허용
- `/frames/*`는 frame-major chunking
- `/labels/*`는 row-major chunking
- mask는 초기에는 packed binary array 또는 payload 저장 허용
- logical meaning만 유지하면 이후 PNG/byte-payload 최적화 가능

### 5. Migration / Loader Compatibility 계약

- `v3.2`는 현재 `canonical1/canonical2 + manifest1/manifest2` 흐름을 즉시 삭제하지 않는다.
- 첫 구현 phase는 target-dataset build root와 bridge layer를 추가한다.
- bridge 규칙
  - 새로운 session store가 target-FPS data의 authoritative source
  - canonical / manifest row는 아래로 session을 다시 연다.
    - `session_h5_path`
    - `frame_index`
    - `event_index_range`
- compatibility 규칙
  - `train/eval/infer` entrypoint는 계속 manifest row를 소비
  - dataset loading은 manifest contract 뒤에서 업그레이드
  - manifest adapter가 생기기 전까지 Stage1/Stage2 runtime 전체를 다시 쓰지 않는다.

고정 구현 순서:

1. target-FPS session writer
2. canonical / manifest bridge row
3. dataset reader extension for `session_h5_path`
4. 필요 시 legacy canonical payload duplication 제거

## 파이프라인

### 1. Dataset Build

- session별로 아래를 scan
  - raw frame
  - raw event file
  - raw CSV availability
  - external Grounded-SAM availability
- `target_fps`로 target timestamp grid 생성
- sensor size에서 target-FPS frame 생성
  - timestamp가 맞으면 raw frame 재사용
  - 아니면 interpolation
- interpolation backend
  - `linear_blend`
  - `timelens`
- 원래 sensor event stream은 그대로 유지
- 각 target timestamp `t*`마다 original event stream에서 packet/window 재구성
  - `t*`에 맞는 event range 탐색
  - packet provenance와 boundary 저장
  - `event_end_timestamp_us == frame_timestamp_us` 보장

### 2. Dataset Annotation

- target-FPS frame마다 annotation row 1개 생성
- Raw-CSV path
  - pupil state `(x, y, w, h, theta)` 파싱
  - `pupil_bbox`
  - `pupil_mask`
  - `pupil_state`
  - eye label은 CSV에서 생성하지 않음
- Grounded-SAM eye path
  - `eye_region_mask`
  - `eye_region_bbox`
- No-CSV session
  - 고정 5-step 순서 적용
    1. `eye_region_mask`
    2. `eye_region_bbox`
    3. `eye_region_bbox`로 ROI crop
    4. ROI 내부 `pupil_mask`
    5. `pupil_bbox`, `pupil_state`
- 모든 frame row는 아래를 기록
  - `sensor_size`
  - `path/id/timestamp`
  - `eye_state_flag`
  - `annotation_status`
  - `annotation_reason`
- blink / closed-eye와 ROI mismatch가 있어도 row는 drop하지 않는다.

### 3. H5 Data Structure

- session당 하나의 `H5` 파일 생성
- 최소 logical group
  - `/meta`
  - `/frames`
  - `/events/raw`
  - `/events/target`
  - `/labels`
  - `/masks`
- 권장 내용
  - `/meta`
    - `session_key`, `user_id`, `eye`, `session_code`, `target_fps`, `interp_backend`, `sensor_size_wh`
  - `/frames`
    - frame payload
    - `timestamp_us`
    - source-pair provenance
    - interpolation alpha / source flag
  - `/events/raw`
    - original `x, y, t, p`
  - `/events/target`
    - `frame_timestamp_us`
    - `start_idx`, `end_idx`
    - `event_count`
    - packet provenance
  - `/labels`
    - eye ROI
    - pupil bbox / mask / state
    - `eye_state_flag`
    - `annotation_status`
    - `annotation_reason`
    - `annotation_source`
    - `annotation_quality`
  - `/masks`
    - eye ROI mask
    - pupil mask

### 4. Canonical / Manifest

- 동일한 target-FPS session store에서 `mode1`, `mode2` canonical 생성
- `mode1`
  - synchronized baseline
  - target-FPS frame, rebinned event window, fused annotation row 사용
- `mode2`
  - 같은 target-FPS base 사용
  - interpolation provenance 및 synthetic-frame metadata 추가
- canonical row는 아래를 복구할 수 있어야 한다.
  - session `H5` location
  - frame index
  - event packet boundary
  - annotation status / reason
  - eye-state flag
- manifest row는 skip 및 invalid reason을 보존해야 한다.
  - session-level skip은 `canonical_skipped_sessions.jsonl`
  - frame-level invalid row는 manifest-side skipped output에 남기고 silent drop 금지

## 검증 기준

- target timestamp grid는 monotonic이며 session time range 안에 bounded
- interpolated frame은 sensor size를 유지
- 모든 target frame에 matching event packet/window 존재
- `event_end_timestamp_us == frame_timestamp_us`
- `H5` group 구조가 complete하고 internally consistent
- 모든 target frame이 annotation row를 생성
- CSV session은 pupil bbox / mask / state를 정확히 생성

- canonical row는 frame/event/annotation provenance를 보존
- manifest는 skip reason을 숨기지 않음
- `mode1`, `mode2`가 새 target-FPS 계약에서 smoke test 통과
