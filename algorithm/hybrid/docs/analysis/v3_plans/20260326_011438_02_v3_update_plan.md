# HBTXR_v3_0 상세 구현 및 운영 계획 v2

Role:
- `XR ML 아키텍트`
- `데이터셋 스키마 엔지니어`
- `학습 시스템 설계자`

## 요약

- 이 문서는 `HBTXR_v3_0` 초기 구현 단계에서 요구된 상세 구현 및 운영 계획을 정리한 기준 문서다.
- 기본 방향은 다음과 같다.
  - 데이터 표현은 `FACET baseline`을 기준으로 삼는다.
  - backbone과 hybrid tracking 구조는 `HBTXR-v2_1-main`의 transformer 기반 구조를 유지한다.
  - 입력 ABI는 `frame [B,1,256,256]`, `event [B,2,256,256]`, `prev_state [B,6]`을 중심으로 고정한다.
  - event dataloader는 `time_bin`과 `fixed_count` 두 정책을 모두 지원해야 한다.
  - resize 정책은 `FACET-style`을 기준으로 하며 기본값은 `facet_square_direct`이다.
  - 실험 디렉토리, CLI, resume/eval/infer/visualize 재실행 규칙은 `experiment.name` 중심으로 통합한다.

이 문서는 이후 `v3.1`, `v3.2`, `v3.3+` 계획 문서로 세분화되기 전의 상위 설계 기준으로 읽어야 한다.

## Event dataloader와 FACET-style resize

### 공식 데이터 설정 키

```yaml
data:
  input_size: [256, 256]
  resize_policy: facet_square_direct
  event_builder:
    policy: fixed_count        # time_bin | fixed_count
    time_bin_us: 5000
    event_count_target: 5000
    accumulation: fast_causal_linear # plain | causal_linear | fast_causal_linear
    causal_weight_power: 1.0
    fast_causal_limit: 25.0
    polarity_split: true
```

### Event dataloader 정책

- `time_bin`
  - `[end_timestamp_us - time_bin_us, end_timestamp_us)` 구간 이벤트 선택
  - 이벤트 수는 가변일 수 있으나 최종 voxel shape은 고정
- `fixed_count`
  - `end_timestamp_us` 이전 최근 `N=event_count_target`개 이벤트 선택
  - 이벤트가 부족하면 가능한 범위만 사용
  - 최종 voxel shape은 고정

두 정책 모두 동일한 최종 tensor ABI를 반환해야 한다.

```text
event: FloatTensor[B, 2, 256, 256]
```

### FACET-style resizing

- 이름
  - `facet_square_direct`
- 동작
  - eye ROI 또는 pupil-centered ROI를 잘라낸 뒤 padding 없이 바로 `256x256`으로 warp resize
- frame
  - bilinear resize
- mask
  - nearest-neighbor resize
- event voxel
  - channel-wise linear resize
- ellipse / box 좌표
  - 동일 affine warp로 함께 변환

추가 지원 옵션:

- `facet_square_direct`
  - 공식 기본값
- `letterbox_square`
  - 비교용
- `sensor_full_square`
  - ablation용

## 모델 및 Scheduler ABI

### 입력

```text
frame input : [B,1,256,256]
event input : [B,2,256,256]
prev_state  : [B,6]
```

### Embedding 및 backbone

```text
Frame Embedding : Conv2d(1, 192, kernel=16, stride=16) -> [B,256,192]
Event Embedding : Conv2d(2, 192, kernel=16, stride=16) -> [B,256,192]
Adaptor         : modality projection -> [B,256,192]
Partial DeiT-Tiny shared backbone -> pooled [B,192]
```

### Head

```text
Eye Region Head          : [B,192] -> [B,5]
Pupil Search Head        : [B,192] -> [B,7]
Pupil Region Offset Head : [B,384] -> [B,8]
Mask Head                : token/grid decoder -> [B,1,256,256]
```

### Decoded state contract

```text
search/state : [B,6] = (x,y,a,b,u,v)
track/pupil  : [B,8] = (dx,dy,dloga,dlogb,du,dv,conf,quality)
track/state  : [B,6]
```

### Runtime scheduler

- `Search`
  - frame branch 기반 relocalization
- `Track`
  - event branch + `prev_state` residual update
- 입력 신호
  - `search_conf`
  - `track_conf`
  - `track_quality`
  - `event_density`
  - `similarity`
  - `closed_eye_flag`
- 구현 위치
  - host-side FSM

## Training 및 Loss

### 2-stage training

- `Stage1 Search Pretrain`
  - 입력: `frame`, `mask_target`, `eye_target`, `pupil_search_target`
- `Stage2 Hybrid Finetune`
  - 입력: `frame`, `event`, `prev_state`, `pupil_track_target`, `constraint_center`

### 손실식 요약

```text
L_stage1 =
  λ_eye_bbox L_eye_bbox +
  λ_mask L_mask +
  λ_search_xy L_search_xy +
  λ_search_ab L_search_ab +
  λ_search_trig L_search_trig +
  λ_search_gwd L_search_gwd +
  λ_search_conf L_search_conf +
  λ_constraint_center L_constraint_center +
  λ_aux L_aux

L_stage2 =
  λ_search L_stage1(search branch) +
  λ_track_xy L_track_xy +
  λ_track_ab L_track_logab +
  λ_track_trig L_track_uv +
  λ_track_gwd L_track_gwd +
  λ_track_conf L_track_conf +
  λ_track_quality L_track_quality +
  λ_consistency L_consistency +
  λ_constraint_center L_constraint_center +
  λ_aux L_aux
```

### 추가 규칙

- `constraint_center`
  - eye ROI 중심 또는 stage1 search center를 target center로 사용
  - decoded pupil center가 제한 반경 밖이면 penalty 부여
- 품질 게이팅
  - `annotation_quality`는 per-sample loss weight
  - `closed_eye_flag=1` 또는 `mask_valid=0`이면 geometry / mask loss 약화
  - `valid_track=0`이면 track geometry 및 consistency masking

### 유지 요구사항

- `Train / Eval / Inference / Visualization`이 동일 `EXPERIMENT_NAME` 아래 존재

  --experiment-name stage1_mode1_train_a \
  --device cuda:0 \
  --num-workers 4 \

sh scripts/hbtxr_mode_pipeline.sh eval \

- 입력
  - `frame [1,256,256]`
