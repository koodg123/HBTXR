# HBTXR 손실 함수 카탈로그

최종 갱신: 2026-03-30 KST

## 요약

이 문서는 현재 `HBTXR_v3_0` 코드베이스에 존재하는 손실 함수들을 “공통 유틸리티”, “primitive loss”, “stage loss”, “distillation / regularization” 네 층으로 정리한 카탈로그입니다.

현재 active 손실 구현은 아래 파일에 분리되어 있습니다.

- `src/hbtxr/loss_common.py`
- `src/hbtxr/loss_primitives.py`
- `src/hbtxr/loss_stage.py`
- `src/hbtxr/loss_distillation.py`
- `src/hbtxr/training/losses.py` (`re-export facade`)

## 0. 공통 ABI와 상태 정의

### 0.1 Active model input ABI

- `frame`: `FloatTensor[B, 1, 256, 256]`
- `event`: `FloatTensor[B, 2, 256, 256]`
- `prev_state`: `FloatTensor[B, 6] = (x, y, a, b, u, v)`

### 0.2 Active head output ABI

- `search/eye`: `FloatTensor[B, 5]`
- `search/pupil`: `FloatTensor[B, 7] = (x, y, a, b, u, v, conf)`
- `event/pupil`: `FloatTensor[B, 7]`
- `track/pupil`: `FloatTensor[B, 8] = (dx, dy, dloga, dlogb, du, dv, conf, quality)`
- `search/mask_logits`: `FloatTensor[B, 1, 256, 256]`

### 0.3 Active dataset target ABI

- `mask_target`: `FloatTensor[B, 1, 256, 256]`
- `eye_target`: `FloatTensor[B, 5]`
- `cur_state`: `FloatTensor[B, 6]`
- `pupil_search_target`: `FloatTensor[B, 7]`
- `pupil_track_target`: `FloatTensor[B, 8]`
- `constraint_center`: `FloatTensor[B, 2]`
- `annotation_quality`: `FloatTensor[B]`
- `event_density`: `FloatTensor[B]`
- `closed_eye_flag`: `FloatTensor[B]`
- `mask_valid`: `FloatTensor[B]`
- `valid_track`: `FloatTensor[B]`

### 0.4 상태 표현

Search / absolute state:

\[
\mathbf{s}_t = (x_t, y_t, a_t, b_t, u_t, v_t)
\]

Track / residual state:

\[
\Delta \mathbf{s}_t = (dx_t, dy_t, d\log a_t, d\log b_t, du_t, dv_t)
\]

Decoded track state:

\[
\hat{\mathbf{s}}_t = \text{decode\_track\_state}(\mathbf{s}_{t-1}, \Delta \hat{\mathbf{s}}_t)
\]

## 1. 공통 유틸리티 (`loss_common.py`)

이 레이어는 대부분의 손실이 공유하는 수학/마스킹/가중치 연산을 담당합니다.

### 1.1 Reduction / weighting

- `weighted_reduce`
- `build_sample_weight`
- `_sample_quality`
- `_geom_mask`
- `_track_mask`

역할:

- annotation quality 반영
- closed-eye 샘플 마스킹
- track 유효 샘플 마스킹

즉 “샘플을 얼마나 믿을 것인가”를 공통 규약으로 고정하는 층입니다.

### 1.2 상태 변환

- `normalize_uv`
- `uv_to_theta`
- `decode_track_state`
- `state6_to_xywht`

역할:

- `uv` 방향 벡터 정규화
- residual track 출력을 absolute ellipse state로 decode
- state 표현 간 변환

### 1.3 기하 손실 보조 함수

- `state_to_covariance`
- `mat_sqrt_2x2`
- `ellipse_gwd_like`
- `ellipse_gwd_loss`
- `box_cxcywh_to_xyxy`
- `box_iou_xyxy`

역할:

- ellipse state를 covariance 기반 기하 표현으로 바꾸기
- box IoU / GWD 계열 손실 계산의 기반 제공

### 1.4 기본 masked loss wrapper

- `smooth_l1_with_mask`
- `sigmoid_bce_with_mask`
- `trig_l2_loss`
- `mask_bce_dice_loss`

이 함수들은 stage loss에서 직접 재사용됩니다.

## 2. Primitive loss 라이브러리 (`loss_primitives.py`)

이 파일은 “현재 바로 쓰는 손실”과 “실험용 후보 손실”을 함께 보관하는 확장 라이브러리입니다.

### 2.1 Point / box / geometry 계열

- `AdaptiveWingLoss`
- `CIoULoss`
- `GIoULoss`
- `CenterLoss`
- `CornerLoss`
- `CenterHeatmapLoss`
- `CenterOffsetLoss`
- `TrigRotationLoss`
- `EllipseOverlapLoss`

적용 가능 대상:

- eye ROI bbox
- pupil center / ellipse
- 향후 YOLO26 box loss / OBB auxiliary 실험

### 2.2 Confidence / relocalization 계열

- `ConfidenceWeightedMSELoss`
- `ConfidenceAwareRelocalizationLoss`
- `BinaryFocalLoss`

적용 의미:

- confidence가 높은 샘플의 regression을 더 강하게 학습
- relocalization flag supervision
- imbalanced binary signal 학습

### 2.3 Motion / temporal 계열

- `TemporalDisplacementLoss`
- `DisplacementLoss`
- `PropagatedStateLoss`
- `GazeVelocityLoss`
- `EventDensityWeighting`

적용 의미:

- event branch 또는 track branch의 displacement 학습
- 이전 상태에서 현재 상태로 전파된 결과를 직접 supervision
- event density를 loss weight로 활용하는 실험 surface

### 2.4 Cross-modal / consistency / KD 계열

- `AnchorConsistencyLoss`
- `FeatureConsistencyLoss`
- `EventToFrameContrastiveLoss`
- `GazeAngularLoss`
- `PredictionKDLoss`
- `RelationalKDLoss`

적용 의미:

- frame/event representation alignment
- student/teacher distillation
- state / feature / prediction consistency

### 2.5 Stage bundle helpers

- `SearchBranchLosses`
- `EventSearchBranchLosses`
- `TrackBranchLosses`
- `ConsistencyLoss`
- `ConstraintCenterLoss`
- `MaskBCELoss`
- `DiceLoss`
- `EyeRegionLoss`
- `AuxClassificationLoss`
- `HBTXRStageLoss`

이 묶음은 “primitive를 조합해 stage 수준 loss 묶음”을 구성하는 용도입니다. 다만 현재 active trainer는 더 최신인 `loss_stage.py` 경로를 우선 사용합니다.

## 3. 현재 active stage loss (`loss_stage.py`)

현재 학습 루프에서 직접 사용되는 핵심 loss는 `compute_stage1_losses`, `compute_stage2_losses`, `compute_metrics`입니다.

### 3.1 Stage1

Stage1에서 계산되는 핵심 loss:

- `loss_eye`
- `loss_mask`
- `loss_search_xy`
- `loss_search_ab`
- `loss_search_trig`
- `loss_search_geo`
- `loss_search_conf`
- `loss_constraint_center`
- `loss_aux`
- `loss_total`

핵심 의미:

- `eye`: eye ROI bbox + confidence
- `mask`: BCE + Dice 통합 loss
- `search_*`: frame 기반 pupil absolute state supervision
- `constraint_center`: pupil center가 허용 반경 밖으로 벗어나는 것 억제

### 3.2 Stage2

Stage2에서 계산되는 핵심 loss:

- `loss_search_*`
- `loss_event_*`
- `loss_track_xy`
- `loss_track_ab`
- `loss_track_trig`
- `loss_track_geo`
- `loss_track_conf`
- `loss_track_quality`
- `loss_consistency`
- `loss_constraint_center`
- `loss_aux`
- `loss_total`

핵심 의미:

- `search_*`: frame branch anchor 유지
- `event_*`: event-only search branch supervision
- `track_*`: residual tracking branch supervision
- `consistency`: search state와 track state의 괴리 억제

### 3.3 공통 수식 성격

현재 active branch loss의 기본 조합은 아래에 가깝습니다.

- 좌표 / 크기: masked Smooth L1
- 방향: normalized `uv` 기반 trig L2
- 기하: ellipse GWD
- confidence / quality: sigmoid BCE
- mask: BCE + Dice

즉 HBTXR는 “단일 거대 loss”가 아니라, state 성분별로 분해된 다중 손실 구조를 채택합니다.

## 4. Distillation / regularization (`loss_distillation.py`)

이 파일은 teacher-student distillation과 stage-aware SSL regularization을 담당합니다.

### 4.1 Distillation 관련 핵심 함수

- `_feature_distillation_loss`
- `_prediction_regression_distillation`
- `_logits_distillation`
- key-filtering 기반 stage target resolution

적용 그룹:

- `feature_keys`
- `state_keys`
- `prediction_keys`
- `mask_keys`
- `logits_keys`
- `rkd_keys`

Stage별 기본 타깃:

- `stage1`: search 중심
- `stage2`: search + event + track 중심

### 4.2 Regularization SSL

`compute_regularization_ssl_losses()`는 다음 성분을 조건부로 켭니다.

- `feature_similarity`
- `cross_modal_contrastive`
- `state_similarity`
- `prediction_similarity`
- `self_consistency`

즉 distillation teacher가 있을 때와 없을 때를 모두 수용하는 regularization surface입니다.

## 5. 현재 손실 체계의 장단점

### 장점

- head ABI와 직접 대응되는 분해형 supervision
- stage1 / stage2 역할이 명확함
- ellipse 기하를 GWD로 직접 반영
- quality / closed-eye / valid-track 마스킹 계약이 일관됨
- distillation / SSL / auxiliary loss를 opt-in으로 얹기 쉬움

### 한계

- eye ROI는 아직 단순 bbox + conf 구조로, YOLO식 box loss가 아님
- event density는 sample contract에 있지만 active stage loss에서 직접 쓰이지 않음
- primitive loss 수가 많아 보여도 모두 active path는 아님
- 일부 문서는 예전 실험 제안들이 섞여 있었고, 지금은 코드 기준 재정리가 필요했음
